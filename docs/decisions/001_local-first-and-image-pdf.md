## 001. 端末保存＋ファイル書き出し、PDF は画像で貼る

- 日付: 2026-11-06
- 対象: 保存（src/model/storage.ts）・書き出し（src/export/）・ステージの描画（src/render/）

### 決定

作品は端末のブラウザに保存し、端末をまたぐときは作品ファイルの書き出し・読み込みで移す。配るのは場面ごとに1ページの PDF で、各ページは Canvas に描いた画像を貼る。図は「線・文字・丸・矢印」の一覧を1か所で計算し、画面（SVG）と書き出し（Canvas）の両方で描く。

### 背景

使う人は「他の人も見るけど、リンクではなく画像か PDF で共有できればいい」と決めた。作るのはスマホ。曲は使わずカウントで進める。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| クラウド保存・リンクで共有 | 共有はリンク不要と決まった。サーバーとログインの手間に見合わない |
| PDF に和文フォントを埋め込んで文字で書く | フォント埋め込みで数 MB 増え、画面と見た目がずれやすい。配る用途では文字を選べなくても困らない |
| 画面と書き出しで別々に描く | 2か所で計算すると、画面と PDF の位置や色がずれる |
| 曲を読み込んで同期する | 曲は使わないと決まった。カウントとテンポで足りる |

### 影響範囲

- iPhone の Safari は、ホーム画面に追加しないまま7日ほど開かないと保存を消すことがある。README と作品一覧の案内（書き出しから7日で警告）がこれに依存する。
- PDF の文字は選択・検索できない。

### 検証

- 単体テスト47件（保存の読み直し・壊れたデータの退避・読み込みは別の作品として足す）。
- 画面外の Chrome で PDF 2ページを作り、和文が描けていることを確かめた。
- 間違いだと分かる兆し: 「リンクで渡したい」「複数人で同時に直したい」と言われたとき。
